## 2. Drift: stated product vs. shipped product

### 2.1 The product is a DM archive, not a saved-posts archive

`PRODUCT.md:7-11` leads with "saved reels and posts, and direct-message threads". The data says the opposite: **95.5% of the vault is DM-shared content from a single conversation.** Saved posts are a rounding error.

Every downstream decision inherits this error. The dashboard is the saved-posts grid and is the app's home route; `/messages` — where 95% of the content actually lives — is the second nav item and holds exactly one thread.

**Consequence:** the primary surface is optimised for the smallest slice of the corpus.

### 2.2 The enrichment pipeline is the product's spine, and it has never run

`PRODUCT.md:9-10` promises AI summaries and tags. `0 of 198` items have one.

The reason is a chain of preconditions that has never been satisfied end to end:

1. `GROQ_API_KEY` must be set — ✅ it is.
2. The Python sidecar must be running, because `convertToMarkdown` (`src/lib/ig.ts:26`) proxies to it; without the sidecar every enrichment runs on title alone.
3. The user must be on `/connect`.
4. The user must complete a **sync**, because the "Enrich with AI" button only renders inside the `{result && ...}` block (`src/app/connect/page.tsx`) — the button does not exist on page load for an already-connected account.
5. The user must press it **10 times**, because `/api/enrich-pending` processes `listPendingItems(20)` per POST with no queue or loop (`src/app/api/enrich-pending/route.ts`).

**Consequence:** the single feature that turns a hoard into a retrievable archive is gated behind a five-step chain whose trigger is invisible unless you just finished a sync.

### 2.3 Search and chat are querying empty columns

`searchItems` and `/api/chat` rank over `title`, `summary`, `tags`. Two of those three are empty for 100% of items, and the third is generic for 53%.

`/api/chat` sends `{id, title, category, tags, summary}` to the LLM (`src/app/api/chat/route.ts`). For this vault that payload is effectively `{id, "Instagram Reel", "Shared in DMs", [], null}` — **198 near-identical rows.** No model can rank that.

**Consequence:** Chat cannot work on the current corpus. It is not a tuning problem; there is nothing to retrieve on.

### 2.4 The category filter is decorative

Categories are assigned at ingest from `origin`, not derived from content. Two values exist and they restate a field the user already sees. `src/app/page.tsx` renders a category nav that cannot narrow anything meaningfully.

### 2.5 Privacy positioning conflicts with actual data egress

`PRODUCT.md:31` — "Private by default … data stays in the user's own backend." `DESIGN.md` and the footer both sell "Local first · Private · Yours".

But enrichment posts item titles and sidecar-extracted captions to **Groq** (`src/lib/llm.ts:4`), a third-party US API, and the corpus being sent is 95% **private DM content**. Legacy Supabase credentials are also still live in `.env.local`.

**Consequence:** the strongest brand claim is not currently true. This is the highest-severity finding in the audit — not because the egress is large, but because the promise is the product's entire reason to exist over just using Instagram.

### 2.6 Documentation describes a different system

| `CLAUDE.md` says | Reality |
|---|---|
| Enrichment model `claude-haiku-4-5-20251001` via `@anthropic-ai/sdk` | Groq `llama-3.3-70b-versatile` via raw fetch (`src/lib/llm.ts`) |
| `ANTHROPIC_API_KEY` enables enrichment | `ANTHROPIC_API_KEY` is empty; `GROQ_API_KEY` is the live one |
| — | `@anthropic-ai/sdk` remains an unused dependency (`package.json:12`) |
| `PRODUCT.md:32` "ingest is from the official export, not a live magic sync" | The sidecar live-sync **is** the primary path; the export page was removed |

### 2.7 Features built for a user who does not exist yet

`notes` is used on 0 of 198 items across three years of content. The item detail page's primary interaction — and the delete/save/confirm machinery hardened in the last session — serves a behaviour that has never once occurred.

This is not an argument to delete notes. It is an argument that **note-taking is not the job**, and the roadmap should not be built around it.

## 3. Severity ranking

| # | Finding | Severity | Why |
|---|---|---|---|
| 1 | Private DM content is sent to Groq while the product sells "local first, private" (§2.5) | **Critical** | Breaks the core promise |
| 2 | Enrichment has never run; 0% summaries (§2.2) | **Critical** | The spine of retrieval is missing |

| 5 | IA is inverted — 95% of content is behind the 2nd nav item (§2.1) | **High** | Home page shows the smallest slice |
| 6 | 85-day stale sync with no visible staleness signal | **Medium** | User cannot tell the vault is behind |

| 8 | Docs describe a different system (§2.6) | **Low** | Cheap to fix, misleads future work |

## 4. What is genuinely working

Not everything drifted. Worth protecting in the redesign:

- **Ingest is solid.** 198 items and 192 messages across three years, correctly deduped by URL, with original timestamps preserved so ordering reflects when content was *saved*, not imported. That is the hard part and it works.
- **Thumbnails are 100% populated.** Every item has an image. This is the single richest signal in the vault and the redesign should lean on it hard — especially given 53% of titles are useless.
- **The visual system is coherent** and correctly scoped out of this redesign.
- **Local-first storage** (single SQLite file, no cloud DB) is real and worth keeping — the privacy gap is only at the enrichment hop.

## 5. Open questions for the owner

The single user of this product is you, so these cannot be answered from the data. They gate the strategy doc.

1. **Is the DM thread the product?** 95% of content is one conversation. Is Reel Vault "an archive of reels my friend and I trade", or did the saved-posts sync simply fail to pull your real saved collection?
2. **Why did enrichment never run** — did you not know the button existed, did the sidecar not run, or did you try and it failed silently?
3. **What did you last go looking for and fail to find?** The single most valuable input to this redesign, and the only real evidence of the retrieval job.
4. **Is third-party enrichment acceptable** if it is disclosed, or should enrichment be local-only (Ollama) to keep the privacy claim literally true?
5. **Does 85 days stale bother you?** That determines whether sync automation matters or whether manual-on-demand is correct.
